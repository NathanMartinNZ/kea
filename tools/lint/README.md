# tools/lint

`pnpm lint`: the architecture lint. It prints `file:line rule message` for each violation and exits 1 if there is
any. It uses Node builtins only, plus the design tokens that `pnpm codegen` writes to
`packages/ui/src/generated/tokens.ts`.

| Rule | Checks |
|---|---|
| `boundaries` | Every import in `app/*/src` and `packages/*/src` (in a `.svelte` component, its `<script>` blocks) resolves to the package's own files or to a package in its `package.json` dependencies (test files may also use the root devDependencies). `app/renderer`, `packages/ui` and `packages/terminal` never import Node builtins or `electron` (test files excepted). `packages/*` never import `@kea/main\|core\|ptyhost\|renderer\|preload`; one process never imports another's package; no relative import of another package's files; `@kea/x/sub` only if listed in x's `exports`, and `#name` only if listed in the package's own `imports`. |
| `tokens` | Over `app/renderer/src` and `packages/ui/src` (`.css`, `.ts`, `.svelte`) and `app/main/src` (`.ts`, for the window's colours), not `generated/` and not tests: no raw hex, `rgb()` or `hsl()` colours; no `font-size` above the largest type size (rem counts as 16px); `border-radius` only `var(--radius-*)`, `0` or `50%`; padding, margin and gap only `0`, `1px`, `2px`, a step of the spacing scale (`--space-*`) in px, `var(--space-*)`, `var(--size-*)` or `auto`. Checks CSS files, CSS text in TS strings, and style objects (`fontSize: 16` is px). In a `.svelte` component: `<style>` blocks, `<script>` blocks and markup `{…}` expressions as TS, `style="…"` attributes, `style:prop="…"` directives (a value with a `{…}` part is checked for colours only) and raw colours in any other quoted attribute (`fill="#fff"`). |
| `agent-strings` | Agent-specific flags, env vars, payload fields and paths never appear in `app/` or `native/kea-helper/src` code (tests, `#[cfg(test)]` modules, comments and `.md` excepted; a `.svelte` component's markup text and attributes count as code, its HTML comments do not). The list is the seed in `agent-strings.ts` (flags such as `--session-id` and `--resume`, the env vars `CLAUDECODE`, `CLAUDE_CODE_*` and `ANTHROPIC_*`, payload fields such as `hook_event_name` and `transcript_path`, paths such as `~/.claude` and `.commandcode`) plus the agent-looking string literals (flags, env vars, snake_case fields, dot-paths) of every `packages/adapters/src/*/contract.ts`. |
| `os` | Outside `os/` folders and their tests, everywhere in the repository (`app/`, `packages/`, `tools/`, `tests/`, `native/kea-helper`; not `fixtures/`, generated files or this tool): reading which system this is (`process.platform`, `os.platform()`, `os.type()`, `navigator.platform`, `platform` / `type` imported from `node:os`); absolute paths of system tools and folders (`/usr/bin/`, `/usr/sbin/`, `/sbin/`, `/System/`, `/Applications`, `Library/`, `/proc/`, `/sys/`, `/etc/`; `/bin/sh`, `/usr/bin/env` and `/dev/null` are allowed); in files that import `electron`, the APIs one system has (`app.dock`, `app.hide()` and its kin, `did-become-active`, `systemPreferences`, `Tray.setTitle` / `getTitle`, `trafficLightPosition`, `titleBarStyle`, vibrancy, a macOS-only menu `role`, `Notification` `subtitle`); in Rust, `target_os` (`cfg`, `cfg!`, `cfg_attr`), `env::consts::OS` and the libc symbols one system lacks (`PLATFORM_SYMBOLS` in `os-names.ts`: libproc, `__error`, `_NSGetEnviron`, `SO_NOSIGPIPE`, `LOCAL_PEER*`, `arc4random*`, `SecCode*`, `SO_PEERCRED`, `__errno_location`, …; a symbol in a message string does not count, one in a `c"…"` string for `dlsym` does). Comments are not scanned. |

Exceptions: Kea's own database columns `session_id`, `transcript_path` and `permission_mode` are allowed in `.sql`
files and SQL string literals; anything else needs `kea-lint-allow U-AGT-11: <reason>` on the same or the previous
line. An `os` line is let through by `// os-ok: <reason>` on it or alone on the line above; the summary counts them.

**Code:** `lexer.ts` (comments blanked, string spans; JS/TS, CSS, Rust; `.svelte` split into same-length script, JS,
CSS and attribute projections) · `boundaries.ts` · `tokens.ts` · `agent-strings.ts` · `os-names.ts` · `types.ts` (a
violation and how it prints) · `main.ts`. Tests: `lint.test.ts`.
